# BP Luxe Relove storefront

A static, responsive luxury storefront connected to the existing Shopify store. The landing page retains its video hero, typography, editorial sections and word reveal. The shop adds dedicated category entry points, product pages, native filters, search, saved pieces, a mini bag and full bag, and Shopify checkout.

## Run locally

Use Node 20 or later:

```sh
npm run dev
```

Open `http://127.0.0.1:8000`. Alternatively run `python -m http.server 8000`. Use HTTP; ES modules and the sample catalog cannot run reliably by opening the HTML files directly.

No package install or build is needed to serve the website. Playwright is a development dependency for the optional browser checks, not part of the deployed storefront.

## Live and demo modes

**Live is the production default.** `config.js` preserves the existing public Storefront API credentials and pins API version `2026-10`. The source of live product names, photographs, prices, variants, availability and policies is Shopify. API errors and missing collections never trigger sample data.

Preview `shop.html?demo=1` for **36 fictional sample products** across six categories. The parameter follows internal links. A permanent preview banner and sample descriptions distinguish this mode; its guest bag and wishlist use different storage keys. The demo checkout button is disabled, and the cart code independently rejects checkout and rejects sample IDs in a live cart. The banner's “Return to live shop” link removes demo mode. Do not set `CONFIG.mode` to `demo` for production.

The sample images are original SVG product studies generated by `scripts/create-demo.mjs`, not photographs or representations of designer stock. No external image licenses are required for those studies. Regenerate with `npm run demo:generate`. Existing editorial images remain the site's existing AI-created assets. Actual sale item photographs always come from Shopify. The fonts are self-hosted Cormorant Garamond and DM Sans; their OFL licenses are in `assets/fonts/`.

## Adding and maintaining products

1. Add products in Shopify Admin with accurate descriptions, photographs, prices, vendor/brand, product type, options and variants. Track inventory and configure the correct stock location and shipping settings in Shopify.
2. Publish products and collections to the sales channel associated with the existing Storefront token and the intended market. Keep the development store's password until the owner is ready to launch.
3. Assign products to the collections listed below. The storefront reads updates on page load; no separate product file needs editing.
4. Add and publish the client's actual policy and contact information before taking orders.

Only public Storefront credentials belong in browser code. Admin API keys/private tokens are not used or required by this storefront. Never place them in this repository.

### Collections and routes

All collection handles are maintained in `CONFIG.collections` in `config.js`.

| Route | Configuration key | Current collection handle |
| --- | --- | --- |
| `shop.html` | `all` | `all-products` |
| `handbags.html` | `bags` | `new-arrivals` (existing mapping retained) |
| `shoes.html` | `shoes` | `shoes` |
| `sunglasses.html` | `sunglasses` | `sunglasses` |
| `accessories.html` | `accessories` | `accessories` |
| `fashion.html` | `fashion` | `fashion` |
| `hair-beauty.html` | `beauty` | `hair-beauty` |
| `new-arrivals.html` | `new` | `new-arrivals` |

The test store currently publishes `frontpage` and `new-arrivals`, with one handbag. Other category routes intentionally show an empty edit until their collections are published. For launch, create a separate handbags collection and change `bags` if New Arrivals will include other categories.

An automated `all-products` collection containing all intended sale stock is recommended. If it is absent, All Products still works through native root product queries, exposing the supported price, availability, brand and product-type filters. Advanced option/metafield filters are enabled by Shopify on collection routes; the fallback deliberately does not pretend unsupported filters work.

### Filters and product details

Configure available filters in Shopify Search & Discovery. The interface uses the filters and counts returned by Shopify, rather than hardcoded lists of live colors, brands or sizes. Collection filtering and sorting happen through Storefront API queries. Pagination uses cursors; counts use lightweight paginated ID queries when the collection API does not provide a total. It does not download every product's details to filter locally. Search uses Shopify search/predictive search and its result counts. Shopify search exposes relevance and price sorts; catalog collections additionally expose newest and alphabetical sorts.

Optional product metafields in namespace `custom`:

| Key | Suggested type | Display |
| --- | --- | --- |
| `condition` | Single line text | Condition label and details |
| `material` | Single line text | Material |
| `dimensions` | Single line text | Product dimensions |
| `included` | Multi-line text | What is included |
| `authentication` | Multi-line text | Actual authentication/certificate information |
| `style` | Single line text | Style |
| `care` | Multi-line text | Care instructions |

Enable storefront access for these definitions and configure supported metafields as filters in Search & Discovery where appropriate. The metafield keys are listed in `CONFIG.metafields`. Do not add an authentication provider or certification claim unless it is true for that product.

Product pages use `product.html?handle=the-shopify-handle`. Product variants and galleries load dynamically; selected variants are shareable in the URL. Product options support more than the first variant page. Missing or unpublished products have a clear unavailable state.

## Cart and checkout

The live bag uses Shopify `cartCreate`, `cartLinesAdd`, `cartLinesUpdate`, `cartLinesRemove` and cart retrieval. It stores the Shopify cart ID locally and restores server prices and lines after refresh. The mini bag and full bag share the same state and serialized mutations. Variant availability, Shopify warnings and user errors are shown. Stock is not reserved by the wishlist or bag.

The existing token lacks `unauthenticated_read_product_inventory`, so the site does not request or display exact stock counts. It uses `availableForSale` and Shopify's stock validation instead. Checkout refreshes the Shopify cart and navigates to its generated HTTPS `checkoutUrl`; there is no fake checkout, payment form or permalink fallback. The development store currently redirects this URL to its password page. That restriction is preserved.

## Information pages

About, Contact, FAQ and Authentication first read Shopify pages with handles `about-us`, `contact`, `faq`, and `authentication`. In their absence, About/FAQ/condition guidance provide honest general storefront information. Contact displays the approved details in `config.js`; an email form is available only when `contactEmail` is configured and explicitly opens the visitor's email application.

Delivery, Returns, Privacy and Terms read the published Shopify shop policies. If a policy is unpublished, the page says so. No invented legal terms, delivery promises, company addresses or certifications are substituted. The test store currently returns a privacy policy, but no shipping, refund or terms policy. All client content still needs the owner's review.

## Structure

- `index.html`, `styles.css`: preserved landing page and base design.
- `shop.css`: shared commerce layouts and responsive styles, using the site's desktop scale.
- `config.js`: public credentials, collection handles and approved brand/contact settings.
- `storefront-api.js`: Shopify requests, retries, native queries, pagination and normalization.
- `ui.js`: shared shell, responsive navigation, modal/focus handling, image rendering and metadata.
- `cart.js`: live and isolated sample bags, persistence, mutation queue and guest wishlist.
- `app.js`: catalog, product, search, saved pieces and information views.
- Category and supporting `.html` files: static hosting entry points with their own metadata.
- `demo-catalog.js`, `demo-products.json`, `assets/demo/`: explicitly selected preview data and original art.
- `tests/storefront.cjs`: browser regression checks. `test-artifacts/` contains generated screenshots and is ignored by Git.

## Verification

```sh
npm install
npx playwright install chromium
npm test
```

The runner starts its own local server. It can use an installed Chrome/Edge on Windows, Playwright Chromium, or `CHROME_PATH`. Use `TEST_BASE_URL` to test an existing local server. The suite tests demo features offline and explicitly checks that a failing live API never becomes a demo catalog. See `VERIFICATION.md` for the actual checks performed against this test store. No automated test submits an order or payment.

Optional real-store checks: `node tests/live-shopify.mjs` reads the configured live catalogue. Add `--cart` to create and then empty a disposable Shopify cart and verify its generated checkout URL. This is an explicit test-store operation and does not submit an order.

## Deploy

Upload the `.html` entry points, `styles.css`, `shop.css`, the root JavaScript modules, `demo-products.json`, and `assets/` together to GitHub Pages or any static HTTPS host. Preserve relative paths and letter case. No server routes, URL rewrites, backend or build step are required. Do not deploy `node_modules`, test artifacts, private credentials or local `.env` files.

Set `CONFIG.siteUrl` to the final site base URL, including its trailing slash and any GitHub Pages repository subfolder. Keep `mode: 'live'`. Category and product data are client-rendered: page titles, descriptions, canonical links and actual product JSON-LD update in the browser. Social bots that do not execute JavaScript cannot see handle-specific product metadata; pre-rendering product pages would be a separate hosting/build enhancement if required.

Use `LAUNCH-CHECKLIST.md` for the merchant tasks still outstanding. This repository is a functioning storefront; payments, approved policies, actual inventory, shipping and ownership remain Shopify/client configuration tasks.
